## 八、技术要点（本次踩坑）

### 1. 页面会被导航走，导致 JS 上下文丢失

**现象**：抓取过程中页面自动跳到 `space.bilibili.com` 或 `t.bilibili.com`，`window.__all` 全部丢失。

**发生两次**，共浪费约 40 分钟抓取。

**解决方案**：
```javascript
// 1. 用 iframe 当沙箱
const f = document.createElement('iframe');
f.src = 'https://www.bilibili.com/robots.txt';  // 同源即可
document.body.appendChild(f);
// 抓取逻辑跑在 f.contentWindow 里

// 2. 锁定主页面导航
window.location.assign = () => {};
window.location.replace = () => {};

// 3. 清掉页面定时器
const maxId = setTimeout(()=>{}, 0);
for (let i = 1; i <= maxId; i++) { clearTimeout(i); clearInterval(i); }
```

### 2. 数据导出必须走 CDP，不能走 ego_download

**失败方案**：
- `ego_download` 触发 blob 下载 → 45MB 超时
- 页面 `fetch` POST 到 `127.0.0.1:8899` → mixed content 被拦

**可行方案**：
```javascript
// 用 CDP 分批读取（每批 5000 条，约 150 万字符，可完整返回）
const r = await cdp('Runtime.evaluate', {
  expression: `w.__chunks[${ci}].slice(${a},${b}).map(x=>JSON.stringify(x)).join('\\n')`,
  returnByValue: true
});
fs.writeFileSync(`${outDir}\\m${fi}.ndjson`, r.result.value);
```

### 3. chunk 与 __all 会不同步

抓取结束时 `__chunks` 总和可能小于 `__all.length`（最后一批未入 chunk）。

**修正**：
```javascript
const chunkSum = w.__chunks.reduce((a,c)=>a+c.length,0);
const tail = w.__all.slice(chunkSum);  // 补抓这段
```

### 4. JSON 中的换行符会导致行数误判

`Get-Content | Measure-Object -Line` 统计的「行数」不等于记录数（评论含换行）。

**正确做法**：用 Python `json.loads` 逐行解析计数。

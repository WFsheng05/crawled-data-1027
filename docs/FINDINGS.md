## 一、抓取阶段

### 1. 纯 HTTP 客户端会被静默降级

**现象**：用 `requests` / `urllib` / `node-https` 调 `/x/v2/reply/main`，返回 `code=0` 但只有 3~4 条，且 `cursor.is_end=true`。

**原因**：B 站对非浏览器 TLS/JA3 指纹 + 无 `bili_ticket` 的请求做了静默降级——**返回成功，但截断结果**。

**这比直接报错更坑**，因为你的爬虫会「优雅地」认为已经翻到底了。

**解决方案**：在浏览器上下文里 `fetch`（`credentials: 'include'`），即可正常翻页。

### 2. wbi 签名有额外混淆

尝试自签 `/x/v2/reply/wbi/main` 的 `w_rid`：
- 穷举 6 种 key 组合 × 排序/清洗/编码变体
- 全部无法命中页面真实 `w_rid`

**结论**：这一版 `wbi/main` 有额外混淆，硬碰性价比极低。`main`（非 wbi）免签名可用，走它。

### 3. 楼中楼必须算进来

| 口径 | 独立用户数 |
|---|---|
| 只抓一级评论 | 10,479 |
| 一级 + 楼中楼 | **16,485** |

**漏掉 6,006 个「只在楼里说话的人」。**

## 四、数据演进（重要）

分析过程中，口径经历了多次修正。以下是完整演进记录：

| 阶段 | 冲官方 | 支持官方 | 中立 | 说明 |
|---|---|---|---|---|
| 初版（规则） | 7,347 | 425 | 8,469 | 只识别明显表达 |
| 补术语 | 7,604 | 166 | 8,471 | 加入强度黑话 |
| 结构化规则 | 7,942 | — | — | 加入反讽标记 |
| 子代理 5 批 | 7,939 | 605 | 7,697 | 首次逐条重判 |
| 规则覆盖修正 | 7,968 | 616 | 7,657 | 含排期抱怨 |
| **子代理 8 批重判** | **8,132** | **767** | **7,342** | **最终版** |

### 关键教训

**规则判定会系统性低估「冲官方」人数。**

原因：
1. 反讽识别不了（「哪里弱了」被当成肯定）
2. 圈内黑话不认识（「超大上」「借过」）
3. 间接暗示抓不到（只提「陪跑」没提「加强」）

**只有逐条人工/子代理判定才能接近真实。**

## 五、典型误判案例

### 案例 1：反讽被当成支持

```
原文：「哪里弱了，全屏火雨很强的好吧，谁说限定就一定要强了？」
初判：支持官方（因为「哪里弱了」= 不弱）
实际：反讽，冲官方
```

### 案例 2：圈内术语被漏判

```
原文：「超大上真的膨胀吗？设计师之前天猫和安洁不是挺会设计的吗？」
初判：中立（无负面词）
实际：冲官方（专业强度批评）
```

### 案例 3：单一信号被过滤

```
原文：「此恨绵绵无绝期」
初判：中立（无关键词）
实际：冲官方（圈内梗，表达失望）
```

### 案例 4：玩梗 vs 批评

```
「阿一古」→ 中立（纯玩梗）
「阿一古，塔露拉的手呢」→ 冲官方（指向断手设计）
```

**边界极其模糊，只能逐条判断。**

## 六、中立用户的真相

### 7,342 个「中立」中，抽样 50 条发现 5 条实为冲官方

**比例约 10%。**

这意味着：
- 报告中的 8,132 是**下限**
- 真实值可能在 8,800 左右
- 但无法精确定位是哪 700 人

### 中立的主要构成

```
3,199 人  其它零散短评（难以归类）
1,417 人  剧情考据/讨论
  744 人  纯表情/短句
  422 人  纯提问
  405 人  玩梗/接龙
  367 人  许愿/抽卡
```

**这批人确实没表达立场，不是被漏判的批评者。**

### 「中立」不等于「支持」

**关键区分：**

| 行为 | 含义 |
|---|---|
| 「许愿塔露拉，出必还愿」 | 想要这个角色，但没评价强度 |
| 「[汤圆]」 | 纯表情，无态度 |
| 「剧情考据」 | 讨论设定，与争议无关 |
| 「阿一古」 | 玩断手梗，但不一定批评 |

**把他们计入「满意」，是误读。**

## 七、与原视频（BV1d5HF6eEEnn）的对比

该视频的核心结论是「884 人刷了 85% 的评论」。

### 数据层面：基本可信

| 项目 | 原视频 | 本数据复现 |
|---|---|---|
| top884 贡献占比 | 85.0% | **84.4%** ✅ |
| 峰值小时 | 6,504 | 6,502 ✅ |
| 单人最高 | 840 | 990 ✅ |

**他证明了「评论数是虚的」，这个结论成立。**

### 但没回答「有多少人」

| 问题 | 原视频 | 本数据 |
|---|---|---|
| 谁刷了 85%？ | 884 个账号 | ✅ 确认 |
| 有多少人不满？ | 未回答 | **8,132 人** |
| 有多少人支持？ | 未回答 | **767 人** |

### 方法层面的三个问题

1. **只谈刷屏，不谈内容**
   - 评论区几万人在讨论强度设计，视频里只在数刷屏
   - 「讨论的人」和「刷屏的人」被混为一谈

2. **强度可算但没算**
   - 技能倍率、攻击间隔、天赋描述，官方都写了
   - 用公开数值做 DPS / 总伤 / 回转计算，是社区常规操作
   - **不需要私服，不需要解包，纯算术就能复现**

3. **分母是自算的**
   - 视频中的「113,512 条」不是接口字段
   - 接口 `all_count` 是 131,310（含楼中楼）
   - 差额来自他自己的一级评论计数
